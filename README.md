# 調整くんっ！

身内向けの日程調整サイト。△を「調整可・並行調整中・ダメそう」の3つに分けて、全員そろう日をさがす。

- 公開ページ: https://b0544109-nk2.github.io/chousei-kun/
- 見本データで動きを見る: https://b0544109-nk2.github.io/chousei-kun/?demo

## しくみ

| | どうやって |
|---|---|
| 読む | Googleスプレッドシート（リンクを知っている全員が閲覧可）を gviz で読む。開いている募集のIDで絞りこむ |
| 書く | Googleフォーム2つ（募集・回答）に裏で送信。中身はJSON1列なので、シートが日付や数字に化けさせない |
| 公開 | GitHub Pages（GitHub Actions でデプロイ） |
| プレビュー | シートに募集が届くと Apps Script（onSheetSubmit）が GitHub に知らせ、Actions がシートを読んで募集ごとのページ `e/<ID>/` を〆切つきタイトル（OGP）で作る。できるまでの間は `404.html` が `?e=<ID>` に転送するので、すぐ配っても開ける |

シートのタブ：

- **募集**：A時刻／B募集ID／C種類（作成・決定・決定取り消し）／D内容（JSON）。同じIDは下の行（新しい行）が正
- **回答**：A時刻／B募集ID／C名前キー（`n:`＋表記ゆれをそろえた名前）／D回答（JSON）。同じ名前は下の行が正（＝後から直せる）
- **設定**：シートID・config の控え

## はじめに1回だけやること

1. https://script.google.com/ で新しいプロジェクトを作り、`setup.gs` を全部貼って `setup` を実行（許可画面で許可）
2. 実行ログの「シートID」を Claude に伝える → `config.js` を書いて push する
3. プレビューを1〜2分で出すため、`setup.gs` 冒頭の説明どおり GitHub のトークンを作ってスクリプト プロパティ `GITHUB_TOKEN` に入れ、`enableQuickPreview` を実行（やらないと、GitHub の定期実行まかせで数時間かかることがある）
4. GitHub のリポジトリ設定 → Pages → Source を「GitHub Actions」にする（Claude が gh で設定済みなら不要）

## 幹事の使い方

1. トップページで「タイトル・詳細・候補日（時刻つき）・〆切・人数（任意）」を入れて「募集をつくる」
2. 出てきた「回答用のURL」を LINE などで配る
   - プレビュー（〆切つきタイトル）は1分ほどで準備されます。それまではコピーのボタンが「⏳ 準備中」になります（できる前に貼ると、LINE や X がしばらくプレビューを出さなくなるため）。急ぐときは「待たずにコピー」
3. 結果画面の出欠表を見て、日付の行を押し「この日に決める」
   - 決める・取り消すボタンは、募集を作った端末か「幹事用のURL」（結果画面の 📮 の中）で開いたときだけ出ます

## 自分の予定（フリカレ）を作成画面に出す

- 募集を作る画面のカレンダーにだけ、フリカレで予定がある日の印（うすい橙＋右上の点）が付く。選んだ日には予定の中身も出る。出欠表と回答画面には出ない
- 仕組み：Actions が freecal-backup（private）を読みとり専用のデプロイキー（secret `FREECAL_DEPLOY_KEY`）で取り、予定の本文がある日だけを AES-256-GCM で暗号化して `busy.json` に置く（鍵は secret `BUSY_KEY`）。サイトは誰でも見られるが、鍵のない端末では読めない
- 使う端末で一度だけ `https://b0544109-nk2.github.io/chousei-kun/?busykey=<鍵>` を開く（鍵は端末に保存され、URLからは消える）
- フリカレのバックアップは毎日3時。サイト側に反映されるのは次の公開処理のとき（募集が作られたときか、数時間おきの定期実行）
- 鍵をなくしたら：`gh secret set BUSY_KEY` で新しい鍵を入れ、新しい鍵の URL を開き直す

## 気をつけること

- **タブの名前とフォームの質問の文言は変えない**（サイトが名前で探しています）
- シートはURLを知っていれば誰でも読めます。名前と回答以外（メール・電話番号など）は書かない
- 「幹事用のURL」はただの目印です。知っていれば誰でも決定ボタンを押せます。身内用と割り切った作りです
- 間違えて送った回答は、同じ名前でもう一度送れば上書きされます。どうしても消したいときはシートの「回答」タブの行を消す

## ありがちなこと と 直し方

| こんなとき | 直し方 |
|---|---|
| 「この募集が見つかりません」 | 作った直後なら1分ほど待って開き直す。ずっと出るならURLの打ちまちがい |
| 「読みこめませんでした」 | 電波のよいところで「もう一度読む」。ずっと出るならシートの共有が「リンクを知っている全員」になっているか確認 |
| LINE・Xのプレビューが出ない・古いまま | 最初に読んだプレビューを覚えています。URLの最後に `?v=2` などを付けて送り直す |
| プレビューがなかなか準備されない | トークンの期限切れかも（Apps Script のスクリプト プロパティを更新）。急ぐときは GitHub の Actions タブで「pages」を手動実行（Run workflow） |
| 回答が反映されない | 送った人の端末には先に表示されます。シートに届くと全員に見えます（自動更新は30秒ごと） |

## ファイル

- `index.html` … サイト本体（作成・回答・結果）。`?demo` で見本データ
- `config.js` … シートIDとフォームの送信先（`setup.gs` の出力）
- `404.html` … `e/<ID>/` ができるまでの転送
- `tools/build-pages.mjs` … 募集ごとのページを作る（Actions から実行）
- `.github/workflows/pages.yml` … 公開と5分ごとの更新
- `setup.gs` … シートとフォームを作る Apps Script
- `ogp.png` / `favicon.png` / `apple-touch-icon.png` … 画像
